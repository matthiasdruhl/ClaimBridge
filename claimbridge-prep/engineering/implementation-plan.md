# Historical implementation plan

This document preserves the build order used for the hackathon implementation. It is not a current backlog. See the repository [README](../../README.md), [workflow guide](../../docs/claim-workflow.md), and [readiness report](../READINESS.md) for current status.

## Build sequence used

1. Define canonical schemas and transport boundaries.
2. Implement PDF upload, storage, page extraction, and duplicate detection.
3. Add structured provider extraction and exact quotation restoration.
4. Enforce semantic, financial, identity, and provenance validation.
5. Add plan retrieval and the scoped external-source registry.
6. Implement bounded conclusions with explicit unknowns and conflicts.
7. Add clarification-driven revisions and stale-result protection.
8. Build the evidence drawer, action plan, and editable appeal draft.
9. Add Demo Mode using exact packet hashes and retained validated extraction.
10. Run the provider suite, saved workflow verification, browser rehearsal, and final repository checks.

## Deferred categories

- OCR and unfamiliar scanned-document layouts.
- Authentication, production privacy controls, and hosted deployment.
- Clinical medical-necessity reasoning and final-liability calculation.
- Insurer submission integrations and multi-state rules.
- Automated full-browser regression coverage.

The implementation intentionally stopped at a local synthetic-data demonstration with traceable evidence and no appeal-submission endpoint.
