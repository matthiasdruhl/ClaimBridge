# Difficult judge questions

| Question | Defensible answer |
|---|---|
| How do you stop hallucinations? | Bound sources and output shape, validate references/math, preserve unknowns and review semantic support. This reduces risk; it does not eliminate it. |
| Are the citations actually correct? | Local sections are matched to extracted PDF text. External summaries have opened URLs, locators, scope and access dates. Entailment and applicability still need review. |
| Is this legal or medical advice? | The prototype organizes a conditional next step from records. It does not decide medical necessity, guarantee coverage or submit an appeal. Qualified help remains necessary for difficult cases. |
| What accuracy have you demonstrated? | Deterministic artifact and primitive checks only. No measured live-model accuracy or general real-world success yet; see experiment results. |
| Why an LLM? | Variable document language and plain-language explanations benefit from it. Arithmetic, dates, IDs, storage and source eligibility use code. |
| Why not just RAG or ChatGPT with PDFs? | The hypothesis is better maintained claim state, conflict handling and workflow validation. A matched benchmark is still needed; citations alone are not a moat. |
| Doesn't prior approval prove they should pay? | In this fictional plan it establishes proposed scope, not actual location or final payment. The stronger argument uses the encounter record and applicable exception. |
| Why not show the savings? | The recognized amount and corrected adjudication are absent. Claiming a precise savings number would be unsupported. |
| What if the insurer was right? | The office-service counterfactual may support the general exclusion. The system must explain that and change its recommendation. |
| Is it HIPAA compliant? | We make no such claim. This demo is synthetic-only. R14 explains role-dependent applicability and other possible privacy obligations. A real pilot needs a specific assessment. |
| How is data protected? | Local synthetic files, no text analytics, controlled IDs and draft-only output. Authentication, retention, vendor contracts and production security are not yet built. |
| How do insurer differences work? | Retrieve actual plan provisions and procedures rather than a universal coverage template. Unsupported plan types stop definitive routing. |
| What about state differences? | State/plan scope is a gate; residence alone does not choose a regulator. The demo uses explicitly specified federal plan rules, not a 50-state engine. |
| Does external review always apply? | No. It depends on subject, plan and process stage. R04 specifically addresses this category; the initial denial is not a final internal appeal outcome. |
| Who are competitors? | Fight Health Insurance, Counterforce Health and human advocates are relevant alternatives. Their published offerings make 'AI appeals' a weak novelty claim. |
| Who pays? | Consumer, advocate and employer models are hypotheses. Test willingness to pay and incentives before selecting one. |
| Could a payer sponsor bias the advice? | Yes. Disclose sponsorship, separate commercial incentives from evidence/ranking and evaluate recommendations independently. |
| How does this scale? | First prove reliable results across a bounded case set. The architecture permits more documents/sources, but maintaining correct rules is harder than adding database capacity. |
| Is this already built? | This package is preparation: case, schemas, specifications and isolated tests. UI/API/live-model integration are hackathon work. |
| What creates a real startup? | Demonstrated outcome quality, trusted distribution and maintained evidence/workflow infrastructure; none is established by one synthetic demo. |
